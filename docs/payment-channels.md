# 支付渠道接入指南

> 面向「先开发、后拿账号」的网店支付模块。全部主流渠道已**预留**：开发阶段用「模拟支付」跑通订单流程，
> 拿到商户账号后，只需在后台填参数并启用，无需改代码。

## 架构一览

```
结算页（前端） ──选择渠道──▶ POST /api/orders { channelCode }
                              │
                              ▼
                    order.service.createPaymentUrl
                              │
                              ▼
             PaymentProvider（抽象层）──▶ mock / alipay / wechat / bankcard / stripe / paypal
                              │
                下单/回调/退款统一经 Provider 分发
                              │
                异步回调：POST /api/pay/notify/{channelCode}（Stripe 也可用 /api/webhooks/stripe）
```

- 渠道数据存 `payment_channels` 表，`configEncrypted` 为 **AES-256-GCM 密文**。
- 前台 `/api/payment/channels` 只返回渠道 `code/name/available`，**绝不返回密钥**。
- 密钥不硬编码、不入前端、DB 密文存储；主密钥来自环境变量（见下）。

---

## 内置渠道与「预留」语义

| 渠道       | code       | 定位                             | 状态                             |
| ---------- | ---------- | -------------------------------- | -------------------------------- |
| 模拟支付   | `mock`     | 开发/演示，站内模拟支付页        | 开箱即用（启用）                 |
| 支付宝     | `alipay`   | 国内主流 · PC 网页支付           | 预留（RSA2 签名/验签已就绪）     |
| 微信支付   | `wechat`   | 国内主流 · APIv3                 | 预留（签名/验签已就绪）          |
| 银行卡支付 | `bankcard` | 通用银行卡网关（银联/收银台）    | 预留（HMAC-SHA256 验签已就绪）   |
| Stripe     | `stripe`   | 国际主流信用卡 · Stripe Checkout | **真实接入级**：配置密钥即可收款 |
| PayPal     | `paypal`   | 国际主流电子钱包 · Orders v2     | 预留（参数组装已就绪）           |

**三态状态机**（后台与前台统一口径）：

1. **未配置**：无密钥/参数。启用开关被禁用（服务端同样拦截：先配置才能启用）。
2. **已配置**：参数齐全，密钥加密落库。预留级渠道显示「预留 · 待接入」徽标。
3. **可收款（ready）**：已配置 + 网关真实接入。启用后前台才真正可选。

- 预留级渠道（alipay/wechat/bankcard/paypal）实现到「参数组装 + 签名/验签」级别，
  `isReady = false`：即使配置并启用，前台仍显示「暂未开通」置灰——顾客不会选到
  一个必然下单失败的方式。申请到商户账号后，在对应 Provider 内补上「发送 HTTPS
  请求」这一步并把 `isReady` 改为 `true` 即可上线。
- Stripe 为渠道化真实接入：后台填 `Secret Key + Webhook 签名密钥` 后 `isReady = true`，
  启用即可收款。未在后台配置 Stripe 渠道时，回落 `STRIPE_SECRET_KEY` 环境变量
  （legacy 路径，既有订单不受影响）。渠道与 legacy 的下单/退款/对账/Webhook 均支持
  渠道密钥优先、环境变量回落。

## 1. 初始化

1. 设置加密主密钥（生产必填，≥32 位随机值）：
   ```bash
   # .env
   PAYMENT_CHANNEL_ENC_KEY="$(openssl rand -base64 48)"
   ```
2. 建表 + 跑迁移（确保「模拟支付」渠道就绪）：
   ```bash
   npm run db:deploy            # 应用 payment_channels 迁移
   npm run migrate:payment-channels
   ```

> ⚠️ 更换 `PAYMENT_CHANNEL_ENC_KEY` 后旧密文将无法解密，需重新在后台保存各渠道配置。

---

## 2. 后台操作

后台「设置 → 支付渠道」：

1. 找到对应渠道，点「创建配置 / 编辑」。
2. 填写参数（字段见下表）。
3. 开发阶段建议开启「沙箱模式」。
4. 保存后，回到列表把该渠道「启用」开关打开。
5. 前台结算页即出现该渠道；未配置/未启用的渠道显示「暂未开通」置灰。

### 支付宝字段

| 字段         | 说明                                                    | 是否密钥 |
| ------------ | ------------------------------------------------------- | -------- |
| App ID       | 支付宝应用 app_id（沙箱/正式各一个）                    | 否       |
| 应用私钥     | 商户应用私钥（PEM）                                     | **是**   |
| 支付宝公钥   | 支付宝平台公钥（PEM）                                   | 否       |
| 网关地址     | `https://openapi.alipay.com/gateway.do`（沙箱另有地址） | 否       |
| 异步通知地址 | `https://你的域名/api/pay/notify/alipay`                | 否       |
| 沙箱模式     | 沙箱联调开关                                            | 否       |

### 微信支付字段

| 字段           | 说明                                     | 是否密钥 |
| -------------- | ---------------------------------------- | -------- |
| App ID         | 微信 AppID                               | 否       |
| 商户号 mchId   | 微信支付商户号                           | 否       |
| APIv3 密钥     | 32 字符                                  | **是**   |
| 商户证书序列号 | 商户 API 证书序列号                      | 否       |
| 商户私钥       | 商户 API 证书私钥（PEM）                 | **是**   |
| 回调通知地址   | `https://你的域名/api/pay/notify/wechat` | 否       |
| 沙箱模式       | 沙箱联调开关                             | 否       |

### Stripe 字段（真实接入级）

| 字段             | 说明                                  | 是否密钥 |
| ---------------- | ------------------------------------- | -------- |
| Secret Key       | `sk_live_…` / `sk_test_…`（API 密钥） | **是**   |
| Webhook 签名密钥 | `whsec_…`（Signing secret）           | **是**   |
| Publishable Key  | `pk_…`（选填，前端嵌入式收款才需要）  | 否       |

> Stripe 的 Webhook 请指向 `https://你的域名/api/webhooks/stripe`（含金额/币种一致性校验），
> 也可用通用回调 `/api/pay/notify/stripe`。沙箱用 `sk_test_` 密钥即为测试模式。

### PayPal 字段（预留级）

| 字段             | 说明                                     | 是否密钥 |
| ---------------- | ---------------------------------------- | -------- |
| Client ID        | PayPal 应用 Client ID                    | 否       |
| Client Secret    | PayPal 应用密钥                          | **是**   |
| Webhook 通知地址 | `https://你的域名/api/pay/notify/paypal` | 否       |
| 沙箱模式         | Sandbox 联调开关                         | 否       |

> 密钥字段保存后只显示 `••••后4位`，留空即「保留原值」，前端无法回显完整密钥。

## 3. 从沙箱切到正式（上线）

1. 在支付宝/微信开放平台申请到**正式**账号与密钥。
2. 后台编辑渠道：
   - 填入正式版 `App ID / mchId / 密钥 / 证书`。
   - 网关地址改为正式地址（支付宝）。
   - 关闭「沙箱模式」。
   - `异步通知地址 / 回调通知地址` 必须为**公网可访问的 HTTPS** 域名（与网关侧白名单一致）。
3. 保存并确认「启用」。
4. 上线前核对清单（见下）。

---

## 4. 上线前核对清单

- [ ] `PAYMENT_CHANNEL_ENC_KEY` 为随机强密钥，且已妥善备份。
- [ ] `SITE_URL` 为公网域名（回调/跳转地址据此生成）。
- [ ] 网关后台已配置授权回调/通知域名（与 `notifyUrl` 一致）。
- [ ] 域名已启用 HTTPS 且证书有效。
- [ ] 用真实小金额做一笔「下单 → 支付 → 回调 → 订单变已支付」全链路验证。
- [ ] 做一笔「支付成功 → 退款」验证退款走原渠道。

---

## 5. 代码侧说明（申请账号后是否要改代码）

当前 `AlipayProvider` / `WechatProvider` 已实现到 **参数组装 + 签名/验签** 级别（逻辑可单元测试），
但**尚未接入真实下单/退款的 HTTPS 请求**（因无商户账号，避免误扣款）。
申请到正式账号后，只需在对应 Provider 内补上「发送请求」这一步（签名数据已备好），
其余（后台、抽象层、回调路由、结算页）均已就绪，无需改动。
